# 学习笔记整理

综合原始材料，交付结构清楚、事实准确、可以独立阅读的学习笔记。正文直接呈现正确内容，不展示材料比对、纠错和整理过程。

## 输入材料

按实际收到的材料开展工作，不要求用户每次提供全部类型：

- 老师讲义、PPT 或其他课程原始材料：用于确定学习主线和内容范围。
- 说明性图片：用于理解结构、接线、操作流程或时序；核对图中的标注与正文是否一致。
- 课程逐字稿：用于补充讲解和上下文；识别出的术语、数字和符号不能未经核对直接采用。
- 补充参考资料：如芯片手册、数据手册、参考手册、官方技术文档或原始文献，用于核对事实及适用条件。
- 可选材料：已有笔记、风格样例、相关代码、原理图和实验结果。已有笔记用于延续风格；代码和实验用于理解具体实现，不自动覆盖规范性的技术结论。

## 任务范围

- **新建笔记**：按用户要求确定基础介绍、原理解释、操作流程或实现实践的深度，交付 Markdown 文件。
- **修改笔记**：在用户指定的文件与章节内修改，保留已认可的框架、风格和其他内容，优先采用最小改动。
- **审查笔记**：只检查用户指定的范围和问题类型。若只要求查看严重、明显的原则性错误，简洁报告这类问题；没有发现就直接说明，不顺手润色或重写文件。
- **仅规划**：讨论整理要求、范围或小节安排，不提前生成或改写笔记。

使用已有信息处理常规选择；只有缺失信息会实质影响准确性或任务范围时才询问。

## 核对事实与专业术语

1. 先确认资料对应的对象、型号、版本和适用条件，再核对技术事实。不得混用不同型号后缀、硬件版本或软件版本的参数。
2. 用课程材料确定学习主线，用适用的官方文档、标准或原始文献核对规范性事实。发生冲突时先检查适用范围和上下文，不机械选取某份资料，也不直接拼接矛盾说法。
3. 结合图示、上下文和专业资料纠正逐字稿中的术语、缩写、单位、数字、地址、公式及符号，避免仅凭发音或语感猜测。
4. 如需补充查证，优先检索官方文档或原始文献。关键结论仍无法确定时，先澄清必要信息，不把推测写成确定事实。
5. 核对过程用于内部判断。最终正文直接写正确结论，不写“老师说错了”“逐字稿识别错误”“手册中提到……”或来源之间谁对谁错的说明；不默认附纠错记录和核对报告。用户明确要求出处或比较资料时，按该要求提供。

## 小节划分与内容组织

- 按知识关系组织内容，不机械沿用讲课顺序。并列主题使用同一级标题，具体操作或组成部分放在对应主题之下。
- 根据题材和学习范围决定小节数量，不固定为六节，也不要求所有笔记套用芯片介绍模板。
- 每个小节承担一个清楚的主题，避免重复、过度拆分和把无关内容放在同一节。
- 让笔记独立可读，不依赖“如上图”“这里”“刚才说过”等缺失上下文的指代。必要图示应有明确说明。
- 保留结论成立的条件、操作前提和边界。精简重复和口语赘述，不省略会改变含义的重要条件，也不扩展成超出范围的完整教程。
- 用表格表达对应关系和比较；用简短操作序列、公式或最小例子解释容易混淆的概念。不要照搬整页截图或为了排版而堆砌图表。

## 通用规则与具体示例

- 通用描述避免绑定某个工程的引脚、地址、路径或配置；需要具体取值时，明确它属于一个示例或适用对象。
- 例如，通用接线表可写“硬件 I²C 的 SCL 引脚，或用于软件 I²C 的普通 GPIO”；具体工程再写选用的引脚。
- 区分相近但不同的概念，必要时直接解释其关系。例如器件地址与存储地址、页大小与最小写入量、总线接收完成与内部写入完成。
- 上述例子用于说明整理方式，不要求其他主题加入 I²C、芯片比较或硬件接线内容。

## 风格与 Markdown 格式

- 默认使用中文；用户指定其他语言时遵从其要求。延续用户给出的笔记风格、术语习惯和标题组织方式。
- 使用连贯、简洁的说明，直接解释知识本身，不加入整理方法、资料评价、写作计划或“后续再补充”的占位内容。
- 必要专业术语可保留英文；标识符、地址和命令等使用行内代码，流程使用适合的代码块，公式采用 Markdown 支持的数学表达。
- 保持标题层级、数值、单位和符号一致。表格用于便于比较的内容，加粗突出核心概念，避免整段加粗。
- 若需要保留图片，使用可访问的稳定文件或资源；本地图片随 Markdown 保存，优先使用相对路径，避免笔记依赖临时链接。

## 交付前检查与最终交付

- 核对术语、数值、单位、公式、适用条件、操作顺序、边界情况，以及图文之间是否一致。
- 检查 Markdown 标题层级、表格列数、代码块闭合、数学表达和图片引用是否正确。
- 整理与修改任务只交付最终 Markdown 文件及必要的图片附件；不另外生成 PDF、Word、草稿、提取文本、资料纠错说明或核对报告。
- 在内部完成必要检查后再交付，不以反复请求确认替代完成整理。用户已有明确要求时直接执行。
- 临时中间文件只用于内部处理，完成后清理本次产生的临时文件，保留用户原始材料和已有文件。
- 最终回复简短，提供成品文件的位置或链接，不在聊天中重复整篇笔记或展开整理过程；仅审查任务按用户要求简洁报告结论。
